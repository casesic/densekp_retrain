# DenseKP 重训数据集要求汇总

更新：2026-09-29。汇总当前会话已确定的业务要求、数据约束和正式数据集验收项。
“必须”是当前约束；“待确定”尚未定数值或实施方案。试验参数和已完成状态单独列出，
不能把小样例通过当作正式数据集验收通过。

## 1. 数据集服务什么目标

提升 DenseKP 在**给定目标人物框**后的 138 个语义点定位，服务跨相机同一人体的语义点对应。
重点覆盖以下条件，也要保留完整、无遮挡或轻遮挡的人体作为对照。

| 重点条件 | 数据中要体现什么 |
|---|---|
| 多人和相互遮挡 | 同图多个目标、前后遮挡、邻人干扰、肢体交叠；每个框有明确目标身份 |
| 较大人体畸变 | 真实相机模型和 ERP 展开产生的畸变，覆盖不同位置、距离、大小和朝向 |
| 图像／有效成像区域边缘 | 身体接近或跨出图像、镜头有效区边界；保留真实 mask 形状 |
| 人体不完整 | 区分镜头／图像截断与实际裁剪排除，不能统一叫“遮挡” |
| 骑行姿态 | 前倾／较直立、不同屈腿和踩踏相位、不同手臂姿态及观察方向 |

只负责 DenseKP 数据、训练及评价。人体检测召回、跨相机匹配、最终合图不作为本任务的
优化目标。模型比较使用相同目标、图像和框；不能通过改变框或丢弃失败预测制造提升。

## 2. 人体姿态来源和几何

- 当前主线必须是：**公开 2D 骑行图片 → 人体重建 → SMPL-X 几何 → 重新渲染**。
  BVH 仅保留备用，当前不继续该路线。
- 不要求自行车资产，允许“虚空骑车”；不把没有车视为本轮不合格理由。
- 单张图片得到的是独立估计姿态，不是连续 motion。不同人的姿态分别保存自己的 shape、
  pose 和来源，不能拼成共享 shape 的连续序列。
- 记录原图、目标人物 ID、原始框、来源 URL、数据源关系证据、可用关节标注和逐图许可信息。
  不能把不同图片的许可统一描述成任意用途可用。
- 重建结果需要原图叠加、多方向网格检查及可用关节重投影诊断；明确深度、手指、绝对尺度等
  未经独立验证的部分。重投影小不等于真实 3D 正确。
- SMPL→SMPL-X 必须经过有依据的模型对应和拟合，保存转换残差及参数还原验证。
  禁止把 72 维直接补零成 165 维，或默认两个模型的 betas 等价。
- 保存源相机坐标到场景坐标的变换、单位、root/pelvis 处理及摆放高度。
  图像重建的估计相机平移不能直接当作真实场景轨迹。

## 3. 人物外观与场景

- **不能局限于一个人物：需要多个不同长相的女性角色和多个不同长相的男性角色。**
  人物差异应覆盖脸部外观、体型、肤色、发型等；具体人数、比例和资产来源待确定。
  仅给同一个人换衣服、颜色、位置或视角，不能计为新增独立人物。
- 分别记录姿态来源、人体 shape 和外观角色身份。多个姿态不等于多个长相，
  SMPL-X 的 `neutral/male/female` 模型选项也不能证明已经具备人物外观多样性。
  改变人体 shape 后，需重新生成匹配的网格、衣物和 138 点，并重新验收。
- **人物必须穿衣服。** 裸身版本保留为几何诊断，不作为当前正式骑行外观方案。
- 衣物必须匹配对应人物的 shape 和 pose，与人体共用轴变换、抬升、旋转、平移。
  不能直接套用不匹配的旧动作衣物，也不能将衣物独立落地。
- 人体和衣物应参与同一 3D 场景的光照、阴影、深度和遮挡。检查明显穿插、破洞、错位、
  悬浮规则和不合理轮廓；保留多人身体及衣物之间的空间检查。
- 当前选用 `cycling_forest` 和 `urban_street_assets`，保留场景原生灯光。
  不能用单纯平面背景替代这条带光影的 3D 场景路线。
- 正式数据要有不同人物、体型、姿态、服装／颜色／纹理、布局和成像尺度，避免把同一个
  人换位置、换视角重复渲染算成新增独立人物或姿态。
- 图像应足以辨识身体与衣物轮廓，检查采样噪声、模糊、曝光、材质和背景遮挡。
  保存渲染器、采样数、随机种子等实际设置，不能事后猜测旧输出参数。

当前贴身骑行上衣和短裤只是基础原型，不等于已经具备真实衣着多样性。
宽松衣物、布料模拟、鞋袜的范围和比例尚未确定；不能擅自升级成全部必备资产。

## 4. 相机、分辨率和遮罩

- 主要真实目标是 `20260320-riding-dataset3`，使用对应 **20260320 DS** 标定。
  031／0311 的标定另行管理，禁止与 0320 混用。
- 两相机处于同一水平线，光轴朝向相差 180°。保存并验证实际外参；不能凭相机名称猜轴向。
- 真实鱼眼源图为 **2880×2880**，实际使用的 ERP 为 **5760×2880**。
  合成试验允许降低 ERP 分辨率，但图像、LUT、坐标、mask 和裁剪必须同步适配并记录尺寸。
- 同一合成双视角必须来自同一世界中的同一人体几何，只有相机观测不同。
  不能把两个独立摆放的人体投影冒充同步双视角。
- 必须有显式鱼眼镜头 mask 和最终 ERP 有效区 mask。**不能根据 RGB 黑色判定无效区**。
- RGB、实例 mask、人物框和点的 `in_view` 必须遵循相同有效域和遮罩。
  表面遮挡检查与镜头有效性检查分开。
- 区分 normal ERP 输入、其他 ERP 旋转、周期经度接缝和物理成像边界。
  不能重复执行 cam4 轴翻转，也不能把经度换边误称为人体被镜头截断。

目前的 0.18 m 基线是合成试验值，不是真实硬件测量，也不是已确定的正式生成参数。
单帧提取的镜头轮廓需要在扩量前检查其稳定性，不能称为精密光学边界。

## 5. 138 点标签和监督规则

DenseKP 输出固定 **138 个语义点**。使用已核验的 `R[138,10475]` 从 SMPL-X 人体网格
生成标签；不能直接使用 SMPL 的 6890 顶点，也不能假定 BEDLAM 的关节或点索引等于 DenseKP。

**RGB、人体网格、衣物摆放和 138 点必须来自同一套几何与坐标变换。**
标签定义在人体上，不因穿衣就改到衣服表面；穿衣后需重新生成图像、深度、实例、框和可见状态。
验证应包含实际渲染世界网格与 `R @ V` 的对照，不能只检查两份同源旧标签相互一致。

| 状态 | 当前处理 |
|---|---|
| 有可靠合成 GT，在镜头有效区和实际完整裁剪内，可见 | 监督，并计入可见组 |
| 有可靠合成 GT，在镜头有效区和实际完整裁剪内，被遮挡 | **仍监督**，并计入遮挡组 |
| 在镜头／图像有效观测区之外 | 不进入当前训练监督 |
| 在有效观测区内，但落在实际完整裁剪之外 | 不进入当前训练监督；另行诊断 |
| 缺少可靠真实 GT | 不用模型预测或拟合结果冒充真实精度评价的 GT |

当前策略为 `supervision_policy='in_view_full_crop'`：

```text
supervised = in_view & inside_full_crop
inside_full_crop: 实际 affine 后的归一化 xy 均位于 [-0.5, 0.5)
```

- `in_view`、`visible`、裁剪包含关系分别保存或可确定地重算。增强后重新判定实际裁剪监督。
- 图像和点共用 affine；完整裁剪是 256×256，网络内部只看中间 192 列。
  输出坐标仍按完整 256-square 定义，左右边带不能擅自排除，也不能额外加 32 px 偏移。
- 标注第三列是生产器明确声明的监督 mask；预测第三列是原始 `keypoint_value`。
  不得因其为数字就解释为置信度或评价权重。
- 不能要求被遮挡点落在目标的可见实例 mask 中，否则会再次取消应保留的遮挡监督。
- 当前可见性是深度／实例近似规则。尚不能可靠细分自遮挡、他人遮挡和物体遮挡，
  因此不能把所有 `occluded` 都标成“被别人挡住”。

## 6. 样本与数据包记录

一个训练样本是**一张图中的一个指定人物框**。同图多人可以产生多行样本，但每行都要
追踪目标身份；目标 ID 和 mask 用于标注与检查，不是当前网络额外输入。

| 信息 | 至少记录的内容 |
|---|---|
| 来源与身份 | 源图片／人物 ID、姿态资产 ID、外观角色 ID 及其衍生关系、来源和许可；合成场景内人物 ID |
| 人体与服装 | 独立 shape/pose、模型与几何来源、衣物来源、未恢复自由度及转换检查 |
| 场景与渲染 | 场景、布局、材质／服装、光照、渲染参数、随机种子 |
| 相机与栅格 | 标定组、相机 ID、内外参、鱼眼／ERP 尺寸及坐标约定 |
| 遮罩与观测 | 鱼眼和 ERP 有效 mask、实例 mask、`in_view`、`visible` |
| 训练输入 | `imgname`、`center`、`scale`、`proj_verts[N,138,3]` 和显式监督策略 |
| 框与还原 | bbox 来源、目标身份、裁剪参数／实际 affine，必要的 ERP roll／旋转信息 |
| 划分与验收 | train/val/test 所属分组、重复来源关系、验收结果和剔除原因 |

这些信息可以分布在训练 NPZ、manifest 和 sidecar 中，不要求全部塞进同一个 NPZ。
按路径、版本、配置和直接数值检查记录来源，**不计算 SHA256**。

## 7. 数据划分和评价

- 正式训练与验证按源人物／图片／姿态资产分组，不能随机拆同源渲染行。
  同一个源人体衍生的相机视角、服装、布局、场景版本不能分到不同集合后宣称人物或姿态独立。
  外观角色的换装、换色等衍生版本也需归组；复用姿态或角色时检查两种来源关系，
  不能只按最终渲染文件名划分。
- 相邻视频帧若以后接入，也不能当作独立样本随意拆分。场景留出与人物／姿态留出应明确
  各自目的；仅换背景不等于完整独立验证。
- 保留单独的真实目标场景给定框评价和完整人体对照。真实未标注图片可做定性诊断，
  不能直接给出有 GT 的准确率；跨相机重建或合图结果也不能代替原始 DenseKP 定位评价。
- 报告全部有效监督点、可见点、遮挡点、裁剪外点、不同边界／畸变／人物大小条件的误差和数量。
  单视角与双视角分别统计，双视角按同一人物、同一语义行对齐。
- 双视角至少区分两边有效观测、两边可见、仅一边可见、两边均遮挡；使用各自 GT 计算
  端点误差，不能直接相减两台相机的像素坐标作为定位误差。
- GT 合格但预测落在镜头外时，仍计入误差，另报拒绝率；非有限预测必须记录为失败。
  空分组不报告成 0 误差；缺少给定框的视图不计为 DenseKP 检测失败。
- 固定原图、目标、框、GT、预处理和评价分母比较 checkpoint。衣物、遮罩等改变输入像素后，
  必须重新推理，不能复用旧预测并当作新输入的结果。
- 明确误差单位与汇总方式：诊断的完整 256-square 像素、ERP 像素、按点平均和训练验证的
  按人平均不能混称。

## 8. 从候选数据到正式数据的验收

| 验收层 | 要检查什么 |
|---|---|
| 姿态和外观 | 来源明确、姿态多方向可解释、人物穿衣、无明显错位／穿插／破洞、图像质量可用 |
| 几何和相机 | 参数还原、网格和 138 点一致、衣物共用变换、双视角同源、投影与 mask 一致 |
| 标签与 loader | 138 行顺序、有限值、监督与可见性分离、实际 crop 往返、增强后监督正确 |
| 覆盖与划分 | 困难条件和完整对照都有覆盖，同源衍生样本无跨集合泄漏，记录数量和分布 |
| 训练流程 | 有限输出／loss／梯度、真实参数更新、覆盖全部验证样本、权重保存重载正常 |
| 模型效果 | 固定基线比较，困难条件是否改善、完整对照是否退化；不能以“训练跑通”代替效果验收 |

正式规模、分布配额、噪声标准、几何误差和模型改善阈值仍需确定。
现有转换门槛、像素往返容差和小规模训练设置属于试验实现，不自动升级为正式业务验收标准。

## 9. 存放和版本管理

- 候选姿态、服装、渲染、标签、预览和实验结果先放 `outputs/experiments/`。
  loader 可以直接读取这里的数据，不要求先移动到 `datasets/`。
- 外观、标签、样本选择和划分确定后，打包到 `datasets/<名称_版本>/`。
  检查图片、mask、几何等依赖，修正活动路径和符号链接，再跑实际 loader。
  不能直接移动含绝对路径的目录后假定它仍可用。
- 原实验与验收证据继续留在 outputs；保留旧版本、旧输出和已有未提交修改。
  新代码、文档、数据和输出在当前仓库；外部 pano-stitch 保持只读。

## 10. 当前状态和待确定项

2026-09-30 更新：已完成 [四角色 × 两姿态接入验收](../rendering/CYCLING_FOUR_CHARACTERS_20260929.md)，
2 女 + 2 男、8 份独立衍生资产、48 张最终预览、两场景 4 张相机图像、13 行 loader。
全部 integration_only；仅证明本轮角色/几何/数据链路接入，未推理或训练，未移入 datasets。

此前有 12 个图片 SMPL 重建、2 个独立 SMPL-X 骑行姿态、两套穿衣场景共 14 个给定框视图。
它们是接入样例，人物、姿态、布局和外观覆盖尚不足以作为正式数据集。
穿衣版已通过几何与 loader 检查，尚未重新推理／训练。
此前裸身版 8 步训练流程通过但误差上升，不能称为模型提升，也不能把其指标用于穿衣版。

2026-09-30 角色目标已确定为 **5 名男性成人＋5 名女性成人，可选 1 名学龄儿童**；
儿童不阻塞成人。三维发型、可辨认的相貌/脸型及体型、初始穿搭差异需要独立验收；
4 运动＋6 通勤为待评审建议。见 [角色规划与缺项](../appearance/CHARACTER_LIBRARY_10PLUS1_PLAN_20260930.md)。

尚未确定：总规模与各困难条件配额、人物外观与更多姿态和衣着来源、
正式 train/val/test 分组清单、
真实给定框 GT 标注范围、正式渲染质量与分辨率组合、完整质量／效果验收阈值。
目前的两个姿态、两场景、0.18 m 基线、1536×768 ERP、32 samples、4 mm 衣物外偏以及
8 步训练，都不是用户已确认的最终数据集规格。

- 当前对话负责执行任务、核验代码与产物、测试和回报结果；已授权范围内的常规实现选择
  自主处理，真正缺失的信息或权限再说明。

  任务交接说明目标、范围、验收条件和资源限制即可；结果回报实际产物路径、验证结果及未完成项。
