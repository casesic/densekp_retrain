# DenseKP 数据格式

## 现有数据加载约定

一个 NPZ 文件包含多组相互对应的数组。`N` 表示人体实例数量，不一定等于图像数量。

| 字段 | 是否必需 | 预期形状 | 代码中的含义 |
|---|---:|---:|---|
| `imgname` | 是 | `[N]` | 与数据集图像根目录拼接的相对路径 |
| `center` | 是 | `[N,2]` | 原始图像像素坐标中的人体边界框中心 `(x,y)` |
| `scale` | 是 | `[N]` 或 `[N,2]` | 边界框尺寸除以 200；加载器最终使用最大边长 |
| `proj_verts` | 是 | `[N,138,3]` | 按固定顺序排列的投影表面点；xy 为原始图像像素坐标 |
| `part` | 条件必需 | `[N,J,3]` | 极端裁剪时使用的二维关节点 |
| `gtkps` | 条件必需 | `[N,J,>=3]` | 关节点的备用来源 |

加载器对图像和点执行相同的仿射裁剪，然后将 xy 除以 256 并减去 0.5。训练过程中不使用相机内参、深度、SMPL 参数、分割结果或网格顶点。

## 建议的生成标注约定

为保持兼容性，应保留上游的四个核心字段，同时增加明确的元数据：

- `proj_verts`：`[N,138,3]`，包含 xy 像素坐标，并明确记录第 2 通道的含义；
- `densekp_visible`：`[N,138]` 布尔数组，表示基于 z-buffer 的可见性；
- `densekp_in_frame`：`[N,138]` 布尔数组，表示点是否位于图像范围内；
- `densekp_depth`：`[N,138]`，表示相机坐标系中的 z 值，与 `proj_verts` 分开保存；
- `camera_K`：`[N,3,3]`；`camera_R`、`camera_t` 应采用一种有明确文档说明的约定；
- `image_size`：`[N,2]`，依次为图像高度和宽度；
- `person_id`、`frame_id`、源序列和数据划分；
- `smplx_*` 参数，或指向源记录的不可变引用；
- `body_model`、性别/模型版本和拓扑标识符；
- `surface_operator_id`，用于记录确切的 138 行表面算子；
- 边界框坐标，以及从边界框生成 `center`/`scale` 的策略。

这种更完整的格式便于审计，也支持后续生成不同畸变域的数据。若要在训练中使用可见性掩码，必须有意识地扩展当前加载器；仅在 NPZ 中增加这些数组并不会改变训练行为。

## 表面点计算公式

对于形状为 `[10475,3]` 的 SMPL-X 顶点 `V` 和暂存矩阵 `R`：

```text
P138_3d = R @ V                   # [138,3]
p_h = K @ (R_cam @ P138_3d + t)  # 齐次透视坐标
p_xy = p_h[:,:2] / p_h[:,2:3]
```

`tools/inspect_surface_operator.py --json points.json` 会导出每一行从 0 开始计数的顶点 ID 及其权重。不要把每一行简化为单个顶点：其中若干行确实是多个顶点的重心坐标组合。
