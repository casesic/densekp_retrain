## 接口与顺序

`parameters(pose,beta,pelvis)` → `parameters_from_pose(pose,beta,pelvis)`。七段切片依次为 `[0:3] / [3:66] / [66:69] / [69:72] / [72:75] / [75:120] / [120:165]`，每段 `np.asarray(...,np.float32)[None]`；随后 betas 使用原对象、transl 使用 `-pelvis[None]`。没有额外长度检查、复制、reshape 或 zero_pose 替代。float32 pose 的内存共享、短输入切片及非法 pelvis 的原异常保留。

`clothing(destination,geometry,rest,joints,short,cid)` → `prepare_simple_clothing(destination,geometry,rest,joints,style_id,character_id,*,style_table)`；short/cid 对应 style_id/character_id，三个调用方均传原 STYLES，不提前查 key。

执行顺序仍是：读身体 vertices/faces → 查 style → clipped_shell → mkdir → 六个几何数组 → 全零 int32 face_material_ids → materials → garment_material → clothing_manifest → str(destination)。保留所有字段、字段顺序、RGB+[1]、integration_only、diagnostic_pending、gate/limitation。算法/坐标/重心绑定无更改；存在目录和写出中途失败没有清理或静默覆盖。

AST 对照确认：新参数函数体与旧体一致（仅名称/说明不同）；新 writer 体在显式参数名称映射后与旧体一致。六个制作/检查 main、fitted_shape、mesh_panel 及原公共函数仅有授权的调用名与 style_table 参数变化，计算和调用顺序不变。这是静态证据，**不是完整 main 运行验收**。
