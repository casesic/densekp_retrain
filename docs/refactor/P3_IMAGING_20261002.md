## 公共实现与阅读顺序

- [imaging/source.py](../../src/densekp_retrain/imaging/source.py)：具名 `SourceERP`，分别读取线性 EXR RGB 或 DS 源预览 RGB；保留原始射线距离与 instance。
- [imaging/ds.py](../../src/densekp_retrain/imaging/ds.py)：`process_scene` 直接组合世界点读取、有效域准备、原始源标签预检查、重映射、标注/框保存、双相机预览。
  `DSDomain`、`DSProjection`、`DSImages` 区分相机域、点结果和图像结果。
- [imaging/omni.py](../../src/densekp_retrain/imaging/omni.py)：`warp_case` 直接组合读取、采样表、重映射、有效域处理、标签、预览和 report；
  `OmniMap`、`OmniBuffers`、`OmniRaster`、`OmniLabels` 区分各阶段数据。
- [imaging/remap.py](../../src/densekp_retrain/imaging/remap.py)：实际共用的周期 ERP 采样和参考镜头轮廓提取。
- [visualization/imaging.py](../../src/densekp_retrain/visualization/imaging.py)：DS/Omni 点预览，颜色/半径/文字保持原行为。

活动调用方直接引用公共模块；旧 pilot 中保留 `process_scene`、`warp_case`、`scalar_reference`、
`draw_overlay`、`remap_periodic_erp`、`lens_mask_from_reference` 的兼容导出。
公共模块无 tools/fisheye 脚本依赖。两个主入口的密集单行语句已展开；
场景、角色、姿态、相机配方及 Blender subprocess 装配继续留在入口。
源代码计算 AST 核查确认其余入口函数计算未变，只有导入和排版变化。

概念阅读顺序为：**读取源数据 → 相机重映射与有效域 → 标签与框 → 保存与预览**。
为保持原异常和文件写出顺序，DS 的源可见性及 roundtrip 预检查仍在图像重映射前完成；
Omni 仍先写 RGB/mask/depth，再核查人物 ID、生成点标签和 report。不能为了外观上的线性流程改变失败行为。

## 深度、插值与历史策略

| 数据/规则 | DS process_scene | Omni warp_case |
| --- | --- | --- |
| RGB 来源 | 已保存 uint8 source preview | EXR Combined 的 float32 线性 RGB；warp 后 linear_to_srgb、`*255+.5` |
| 表面可见性使用的距离 | **原始源 ERP Depth**，光心到表面的射线距离（米） | nearest 重映射到鱼眼后的射线距离（米）；无效/非有限值置 0 |
| 可见邻域 | 原始 ERP 周期 5×5、人物 ID、严格 `<.04 m` | 鱼眼非周期裁边 5×5；有 point_person_ids 时筛人物，否则所有正距离；严格 `<.04 m` |
| RGB/instance 采样 | RGB linear；instance 先 rint 转 float32，再 nearest | RGB linear；原 float instance nearest，按不同消费处分别 `>.5` 或 rint |
| 经度边界 | ERP 左右加一列，周期采样，不环绕极点 | 原 constant border，无 DS padding；不顺带修复接缝 |
| 显式有效域 | resize ERP mask、nearest 镜头 footprint；鱼眼先 mask，回 ERP 再相交 | 反投影 domain 控制采样表；历史 `inside` 只判有限像素与图像边界，不改成模型 domain |
| 保存深度 | 本函数不写 remapped depth；禁止用候选 buffer 替代源距离 | `depth.npy` 是清理后的**鱼眼重映射距离**，不是原始 ERP，也不是 optical-Z |

完整 before/after 的 `raw_source/` 保存 6 个原始 EXR 的 RGB、射线距离、instance、通道和路径。
`*_remaps/` 保存每次 `cv2.remap` 的 x/y 采样表、输出（应用后续 mask 前）、插值和 border 参数。
DS 最终 mask/RGB/人物 mask 另有完整制品，因此 mask 前的实例数据与 mask 后的标签/框均被比较。
Omni remap 原始深度与最终 `depth.npy` 分开比较，没有替换深度阶段。

可靠遮挡 GT 的监督策略未改。DS 继续经过 `validate_ds_scene_pair_pilot.validate` 生成实际 diagnostic_loader；
Omni 继续经过既有 fish→ERP 和 `build_omni_multiperson_tiny.build`，比较全部 train/val 标签及 manifest。
Omni 的 `mask.png` 是物体 mask，不应解释成镜头有效域；DS 不以合成 RGB 黑色判断有效区。
参考照片的阈值/形态学仅用于既有镜头 footprint 提取，不改变该历史方法。
