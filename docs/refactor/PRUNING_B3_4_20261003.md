## 明确新增的 CLI / GPU 前置条件

默认只打印解析计划；仅读 suite 配置及小型训练报告，缺报告或 gate 失败显示原因，不创建业务目录。
计划包含 argv/options、显式/默认模型配置与设备、gate、环境差量、输出、汇总及独立后续命令。
显示计划不检查模型/数据完整性，不等于可以实际推理。

`--execute` 必须显式指定完整 GPU UUID 或物理设备；两者同时提供时必须匹配。
新入口先查询指定设备及进程，解析恰好一个完整 UUID，再将它映射到子进程逻辑 cuda:0。
设备前置检查先于原业务 gate/目录流程，并在每个推理任务前复查；失败明确拒绝，不换卡、reset、kill。
保留原 box 任务的 GPU/process 文本字段；新初始核查通过时另在 stderr 展示结果，不改变业务 JSON schema。
原 source 没有内置核查；这不是完全等价 CLI。没有新增“设备必须空闲”的策略或声称查询可以锁住设备。

原 box 在 GPU 失败时已建目录并读报告；新初始核查失败时不产生这些业务副作用。
这项顺序差异和 source 新增逐任务核查是显式允许的前置条件变更。
