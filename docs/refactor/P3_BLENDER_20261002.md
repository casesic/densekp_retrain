- [rendering/blender/assembly.py](../../src/densekp_retrain/rendering/blender/assembly.py)：共用网格对象创建、基础材质、ERP 相机、

- [groom.py](../../src/densekp_retrain/rendering/blender/groom.py)：既有 Alembic 读取、点/半径替换、曲线裁剪、材质和人物实例 ID。

- [clothing/contracts.py](../../src/densekp_retrain/clothing/contracts.py)：原纯 NumPy `validate_binding`；渲染和普通 Python 校验都直接调用，
  避免公共 Blender 模块反向依赖 tools，也避免纯数值校验依赖 bpy。

`character_materials.py`、`character_groom.py`、`commuter_clothing_contract.py`、`blender_scene_bridge.py` 保留原函数名的兼容导出。
活动 renderer、studio review、commuter validator 直接引用公共模块。公共模块不导入 tools。
`rendering/blender/__init__.py` 不自动导入 bpy；实际子模块仅在 Blender 中使用，不依赖 Torch。
真实 Blender 中的兼容导出 identity 和无 Torch 导入已核查，见 `blender_imports.json`。

两个旧 `--` 入口保留自己的 main 和参数定义；参数工厂 AST 精确不变。
共同步骤变成明确调用，旧密集单行语句展开，但不将两条路径合成一个带大量开关的 renderer。

## 保留的路径差异

| 规则 | 原生多人入口 | 链接单人入口 |
| --- | --- | --- |
| 场景/灯光 | 打开原生 blend，保留 native World、灯光和 look；场景对象 pass_index 归 0 | 空场景读取对象，新建 HDRI/常量 World、SUN；保留隐藏和 ground_mode 策略 |
| 实例 ID | 有 people-config 时身体/衣物/groom 共用人物 ID；旧无 people-config 衣物仍为 2 | 身体 1、衣物 2，场景对象 0 |
| 材质 | appearance/连续衣物/groom 既有配方；通用衣物 roughness .75 | 历史身体纹理；衣物 roughness .6 |
| 设备/seed | 保留原 `--device`、可选 `--seed`、ground-only 校验及检查顺序 | 不新增设备/seed CLI；继续使用 factory 设置 |
| compositor | 原生入口仍显式启用 compositing | 保留 factory 默认，不为统一代码新增状态写入 |
| 衣物和地面 | 逐人物 geometry/binding/studio/ground-contact 拒绝规则原位保留 | 旧共享衣物及 scene_native/remove_ground/procedural 分支保留 |

CV camera-to-world 的列轴为右、下、前；公共 render loop 仍把 Y、Z 列取负转为 Blender 的右、上、后。
全景经纬角仍为弧度；世界/人体/衣物/groom 为米；身体最低 Y 决定共享 lift。
本批不改 P3.3 的图像插值、投影、mask 或监督规则。

EXR 比较保留所有 part/channel 的次序、shape、dtype 和像素：Combined 含 RGB/alpha，另有 Depth、IndexOB。
二进制 EXR 容器的时间等 header 信息不作为像素等价依据。没有改变渲染种子、设备、采样、插值或容差来通过验收。
本次三个相机的旧、新像素均精确一致，未触发“发现不可重复后重新冻结旧实现重复性”的流程；没有另跑旧旧重复实验。
不能据此宣称任意硬件、Blender 版本、样本数或全部资产都可逐位重复。

装配观察器在实际 render 调用前捕获依赖图评估后的网格/曲线，而不是只比较输入 NPY。
允许变化的只有验收输出根目录及观察器的代码位置；装配 JSON 的 `render.filepath` 单列排除：
旧代码在同一行设置 filepath 后渲染，line hook 捕获时尚未写入；展开后的代码捕获时已写入。
它是观察时间差，最终 source_manifest 路径和实际保存制品另行比较。相机矩阵、材质、实例、seed、设备等没有排除。

实际网格到标签的几何校验使用既有 `validate_ds_scene_pair_pilot.py` 的 `5e-6 m` 门槛，
它处理 Blender float32 对象坐标与 NumPy 几何的舍入差，不是本次前后比较的容差。前后对照始终精确一致。
DS 后处理读取本批**原始源 ERP 射线距离**，Omni 使用自己的重映射鱼眼距离，继续分开。
链接路径的 bbox 是验收工具从历史 object mask 派生的检查项，不是给生产 renderer 新增报告字段。
