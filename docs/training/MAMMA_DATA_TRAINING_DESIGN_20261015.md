## 4. 数据格式：原始真值与训练目标分层

建议采用版本化的 `mamma_observation_v1` 旁表/数组，保留已有 R138 产物，禁止原地改写。生成端输出几何与证据；训练 adapter 决定裁剪后目标和 loss-valid，不在编辑器里实现模型 loss。

| 层级 | 必需信息 | 说明 |
| --- | --- | --- |
| 来源/配方 | scene_episode_id、source group、身份家族、组件父引用、recipe revision、master seed、resolved choices | 种子不是独立来源；手绘轨迹与 rig 编辑也要进入冻结配方 |
| 人物/时刻 | person_id、asset/source frame、整数时间、body/topology/template ID、scene_from_model、512 世界点或可重算引用 | 世界点可供多 rig 共用；root 只应用一次 |
| 相机/观测 | rig_id、camera_id、camera_to_world、完整 ERP 尺寸、512 xy、几何可靠/physical domain、visibility 原始状态与证据 | 可见性随相机变化 |
| 栅格存储 | ROI RGB、person mask、physical mask 引用、roi_xyxy、offset、stored_size、render coverage | ROI 外 unknown；共享固定 mask 不逐帧重复保存 |
| 框 | native/predicted/augmented 类型、parent row、完整 ERP xyxy、检测器版本（若有） | 真实检测框和 oracle 框不能混称 |
| 动态 crop | 实际仿射/逆、含滤波 halo 的支持矩形、point_in_crop、框扰动参数 | 训练时计算，不能将一个框的标签复用到另一个 crop |
| 任务有效性 | coordinate_valid、visibility_known/valid、floor_contact_known/valid、contact_known/valid | unknown 与负例分开，必须支持部分标注 |

旧数据可从已资格化身体补坐标，不必重渲 RGB。能从现有网格/场景可靠计算的几何状态可独立补录，但必须记录方法；没有深度的旧数据不能仅靠 RGB、R138 visibility 或模型预测自封为 512 真值。

物理域外、裁剪外、未渲染、可见、被挡、未知是不同原因。即便某任务最终都将其中几项排除，也要保留原因。无框观察槽继续保存，用于可用率分母，不凭空生成模型输入。

## 5. Visibility：首轮最重要的新标签

### 5.1 定义与兼容边界

保存两层：
1. **观测证据**：每点的身体投影/距离、前景距离与实例、物理有效性、邻域支持、遮挡原因。
2. **版本化判定**：visible / occluded / unknown，以及判定方法与容差；再由 crop 构造训练目标。

当前历史 `erp_visibility` 使用 5×5 邻域、同人物 ID 和 4 cm 距离差，且 `j//138` 写死点数；`occlusion_evidence` 也要求 `(N,138)`，并用中心＋3×3 一致性诊断邻人遮挡。它们不是已证实的 MAMMA 512 标签生成器。公共改造应显式传点数/人物索引和 label policy，保留 R138 原行为，不把 138 常量直接全局替换成 512。

**不能仅用同一个人物 ID 判可见。**前臂可能挡住躯干，两者 ID 相同；衣服、头发也使用同 ID。深度量是相机射线距离（米），不能误用相机 Z。ROI 必须覆盖判定所需的邻域；边界和 ID/深度不一致的点标 unknown，不自动当自遮挡。

官方 `vertex_visibility` 的完整生产实现、衣物容差及遮挡阈值尚未核证。需先在官方可读说明/可得小样本中找依据；找不到时采用明确命名的项目几何策略，不能声称逐值复刻官方标签。

### 5.2 建议的小型标签校准

选固定少量点/时刻，覆盖朝向相机、身体背侧、自遮挡、邻人遮挡、背景遮挡、贴身衣物、宽松衣物/头发、轮廓与物理边缘。使用已有全体身体几何的射线/BVH 检查或可用深度作独立参考，不能只让同一深度函数自证。

建议首版只接纳高可信正负例：
- 确认前方是另一人物/场景且距离证据充分：遮挡负例。
- 身体自身可见、对应的本人物表面深度一致：可见正例。
- 本人物 ID 下，无法区分自己肢体和衣物厚度：未知，不能一律可见或一律遮挡。
- 必须显式处理衣物覆盖：身体语义点仍位于身体，不移动 GT 去“贴衣服”；若采用衣物容差，校准并保存版本，不照搬 4 cm。

高可信规则需要确实产出有代表性的可见正例和遮挡负例；若衣物使大部分点 unknown，应改进可见性证据，而不是用极少样本宣称 visibility 数据已就绪。保留未知占比、身体部位和衣型分布。

### 5.3 裁剪外与物理域外

建议第一轮 visibility loss 仅覆盖“几何可靠、物理域内、当前 crop 内、证据已知”的点；可见=1，被挡=0。裁剪外和物理域外默认不参与该 loss，但保存其原因。这是**与原 Dataset 裁剪外置零不同的明确建议**，不是官方原样行为。

若后续需要输出“该点是否在当前输入中可观测”的统一概率，可增加独立的 `outside_as_negative` 配置，将几何可确定的 crop/domain 外点作负例，并单独控制数量和评价。不得把未渲染/证据未知点也设为负例；第一轮 off/on 对照必须用同一种 visibility 语义。

输入 mask 的随机缺损是输入噪声，不改变真实身体可见性 GT；不能因为抹掉 mask 像素就把该点标成物理遮挡。

这是用户尚未最终决定的训练项。推荐不阻塞首轮坐标＋visibility，但先核验少量行走帧的标签可行性。

原 Dataset 读取预制 `floor_contact_mask`，所读仓库中未找到其完整生成规则，因此不能声称官方阈值已知。建议按实际世界几何建立版本化标签：
- 地面只包含明确登记的道路/步道等支撑表面；不是任意最近场景物体，更不是俯视绿色矩形或统一 z=0。
- 世界坐标下计算身体表面顶点到有效支撑表面的距离，记录支撑对象 ID、表面点/法线、距离与判定有效性；多 rig 复用。
- 先在完整身体/足部几何上检查落脚、鞋底偏移和穿地，再选择 512 编号；若 512 中没有真正的接触点，也不能强造正例。
- 骑行脚处于踏板高度或悬空时不是地面接触；没有自行车道具不改变此定义。不要为了生成正例逐帧把骑行脚压到路面。
- 行走支撑期/摆动期、脚滑、悬空、穿地都要检查；root 高度和原道路净空检查不等于逐点接触真值。
- 用正例阈值、负例阈值和中间不确定带，具体米制阈值待小型几何检查后冻结。速度/时间连续性用于诊断，不默认创造额外“必须静止才接触”的官方条件。

允许轻微穿模是画面接受标准，不是接触标签正确性的证明；严重穿地、未知鞋底对应或支撑对象不明时屏蔽该任务。输入中无脚/接触区域的样本可保留坐标任务，不要求每张图都监督 floor-contact。

启用前需要可信正负例与固定评价集。只有几乎全零的骑行标签不足以证明这个头学到了地面接触；验证分别报正例召回、精确率、PR-AUC及负例误报，不用全零准确率当主要指标。

### 6.2 人与人接触：本轮关闭

不建立道路交会 contact 训练支线，不要求摆握手/拥抱数据。contact 输出层保留以兼容原权重；`requires_grad=false`、优化器排除、loss 不调用。没有标签时保持 unknown，不从图像交叠推导接触，也不把允许的身体穿插当作期望交互。

辅助输出随共享特征改变的回归漂移只作诊断；如果未来下游必须保持原接触功能，需要单独评审接触数据、蒸馏或保留旧模型的方案。本轮不默认加入这些方法。

## 7. 场景、随机种子、规模与划分

### 7.1 场景目标按数据集覆盖，不强迫每段全满足

| 场景模式 | 主要贡献 | 不要求每段同时满足 |
| --- | --- | --- |
| 单骑行经过双机交界 | 双路部分人体、尺度和框变化 | 邻人遮挡恢复 |
| 行人＋骑行交会 | 遮挡加重、消失、重现、不同动作 | 每帧两个人都完整可见 |
| 2–5 人分散队伍 | 多人、不同 motion、不同位置/尺度 | 全员挤在一起或各人都有恢复事件 |
| T 形路口/转弯 | 方向变化、正背侧观察 | 所有 rig 都同时双边缘 |
| 完整/轻遮挡对照 | 防止普通定位退化 | 必须是困难条件 |

物理标定、身份/时间正确、实际 crop/邻域有支持是硬条件；双边缘比例、15/15 遮挡恢复、侧视时长等是分组覆盖指标。未满足特定覆盖目标的合法数据可以归到其它类别，不能冒充通过，也不必因此全部丢弃。

相机按完整 rig 整体移动旋转，保持双机相对外参；真实目标仍是 20260320-riding-dataset3，不能混用 031/0311。合成 rig 与真实标定关系如有未核实项必须注明，不能只凭方向相差 180° 称“真实外参一致”。

建议第一轮样本采样预算：约 30% 边缘截断主组、30% 交会遮挡主组、20% 姿态/视角/规模主组、20% 完整轻遮挡控制组。**这是推荐起点，未批准配额。**一个样本可有多个标签，但用于采样时明确主组，避免重复计数；同时统计各点可见性与双路共同支持。

### 7.2 配方与实现现状

冻结配方应包含 master seed、独立随机流、人数/组件选择、实际来源和时间窗、手绘路径、rig 位姿/标定、场景与地图版本、渲染设置、ROI/框策略和 revision。保存 resolved choices，不依赖库版本改变后重新抽出“相同”资产；不要求把所有信息压成一个整数，也不计算资产 SHA256。

当前 [A3 报告](../tools/SCENE_EDITOR_A3_20261013.md)显示：可编辑轨迹/rig、预览和生产已有；编辑器 seed 仅记录，组件重抽尚未接通；城市/河岸 UI 可选人物池也有限。历史种子生成器有组件采样，不代表编辑器已完整接入。后续应复用该公共能力，而非新造第二套组合器。

### 7.3 数据规模和成本

当前 435 条父行只属于三个场景事件，邻帧、多 rig 高度相关；扩帧不是扩独立来源。建议分两步：先做 2–4 个带新标签的代表 episode 验接口，再规划约 8–12 个训练 episode、4–6 个开发验证 episode，覆盖两环境与主要模式。数量是预算讨论起点，不是生成指令或保证足够的正式数据规模。

每段可先沿用约 3 秒、31 个时刻；训练按来源/episode/person 分层抽帧，评价保留连续过程。不要固定宣称每个 episode 都有 31×rig×camera×person 条训练行；无框/域外槽位计分母，合法行另计。

在固定场景与几何下多 rig 渲染，人物每时刻只更新一次，沿用单 Blender＋常驻同步消费者。新增标签先计每帧/每人/每相机耗时及 unknown 比例，再估整批 wall、磁盘峰值和重试预算；不能用单人吞吐估五人生产。

### 7.4 划分与许可

先冻结来源组再抽样组合。最低要求同 episode 的所有 rig/帧/框衍生同侧；同原始 motion 录制邻窗、角色外观同源版本也不能伪装独立来源。推荐首轮使用已有来源隔离方案，但需逐条更新资格，不能照搬旧 pending 状态。

- p1 comfortable/alternate 是同一参与者录制，不作相互独立验证。
- p1/p2 是发布 participant/录制分组；KIT11/KIT425 仅可确认路径不同，演员独立未知。
- M01/M04 与 M02/M03 的保守外观组应纳入分组讨论；一个混合 episode 的遮挡者也按所采用的来源政策检查。
- 两环境尽量同时出现在训练与验证，避免 train 只有城市、val 只有河岸；机位/难度也避免完全混杂。独立环境泛化如要测，单独设协议。
- 已反复观看/调参的场景作为开发/回归集；正式效果需要后续冻结未用于模型选择的数据。预训练暴露未知时如实说明。
- 资产使用范围/许可按现有清单核对；unknown 视频来源保留诊断标记，不默认升级为正式训练/发布资格。本设计不重新做法律结论。

## 8. 框、mask 与成像差距

第一步固定 oracle mask 做有界同图换框挑战，验证 MAMMA 框敏感程度，不直接把 DenseKP 结论套过来。候选含合理平移、收缩、扩张及单边截断；幅度结合实际部署框记录和支持统计冻结，不设置脱离实际的大幅扰动。

生成端预留 MAMMA 384:512 crop、1.2 扩张及实际 Gaussian/interpolation halo 的支持并集；训练读取再校验实际 crop。预留框族与采样分布要有同一个 policy ID；改变策略需重新资格化，不能拿旧 DenseKP 方形包络兜底。超支持记录拒绝，不静默缩框、补黑或反复重抽。

on/off 训练用同一个预先支持完整增强族的父样本交集；增强 off 也不能多吃不支持 on 的简单样本。挑战集按共同 GT 交集比较误差，同时报告原全点结果和点数变化，防止裁掉难点造成虚假改善。

MAMMA 同时依赖 mask。初轮框实验固定 oracle mask，通过同一仿射采样；下一独立阶段引入实际部署分割器的预测框/mask或有依据的 mask 扰动。当前比较入口和用户实际 YOLO 分支未必同一默认配置，必须冻结真实版本、阈值、后处理和坐标还原，不能默认把 Mask R-CNN 基线称为 YOLO 结果。

当前 ROI-only 直接 ERP 保留物理有效域，但省去了真实鱼眼到 ERP 的采样/模糊链。应保留真实视频域差距评价；必要时以后加入可复现的重采样/模糊控制，而不是本批回退全部渲染或宣称画质完全等效。ERP 是球面图，不能直接套透视图的基础矩阵像素直线误差。

## 9. 训练实现设计

### 9.1 模型结构与参数组

保留四头结构以严格加载现有 282 key；不要通过构造 `contact=false` 删除层导致加载不匹配。新增 task/loss 开关与 trainable 参数组，和“是否构造输出头”分离。

推荐首轮学习坐标＋uncertainty、visibility：冻结 ViT 和 mask encoder；训练 query embeddings、共享 decoder、landmarks MLP 和 vis_prob；contact_prob 冻结，floor_contact_prob 暂冻结。只训练末端 MLP 可作为更保守备选，但不是已确定唯一方案。

冻结 backbone 时既要 `requires_grad=false`，也要保持其 eval（ViT 含随机 drop path）；Lightning 的 train 切换不能重新打开冻结模块的随机训练行为。未训练头不进入优化器，不能只设 loss=0 后仍保留 weight decay 更新风险。逐组输出参数名/数量/学习率，训练后检查冻结参数保持。

建议短程起点为 AdamW，训练 decoder/heads 的 LR 1e-5 量级，单 GPU，小 batch＋必要梯度累积；不是已验最优参数。原配置的 warmup、层衰减、lr_backbone 不保证执行，正式入口必须明确实现。先 FP32 校验数值，混合精度若采用需在各对照组保持一致并单独记录。

### 9.2 Loss 与有效性

坐标目标固定由完整 ERP 仿射转 384×512，再各除宽高映射到 [-1,1]。训练 loss 的尺度与评价的 ERP px 不混用。

建议坐标有效性：geometry_reliable ∧ physical_domain ∧ point_in_crop ∧ source_sampling_supported。可见性未知/遮挡不自动清除坐标。visibility 按第 5 节的独立 known/valid；floor-contact 启用时也有独立 valid；contact 本轮完全跳过。

原 NLL 把第三值当 log sigma，同时优化残差项与 2*log_sigma 项。屏蔽坐标时两项必须一起屏蔽；在无效目标可能含 NaN 时先索引有效点，不能用 `NaN*0` 期待清零。全无有效标签的任务跳过并记数量，不做除零或喂入 -1 标签。

原 loss 在全部点上 mean，手脚权重与裁剪外衰减会改变尺度。建议新配置采用“每样本按有效权重和归一化，再按有该任务标签的样本平均”，避免严重截断样本被无意降权；这是明确的 loss 变化，off/on 对照两组保持同一实现，并保存全有效/无有效/部分未知的独立算例。原残差上限 25 和权重乘法顺序也要明确保留或另行评审，不在重构中顺手更改。

visibility 用带 valid mask 的 BCEWithLogitsLoss；floor-contact 如启用用带 valid mask 的 focal loss。首轮不擅自引入 visibility focal、复杂重加权或伪标签；若类别不平衡，先统计再冻结采样/权重。

损失系数不能机械从旧 100:1:1:1 搬入新分母：先记录各项值和梯度量级，用训练侧小试定一个固定配方；不能看验证结果反复调参再报“独立验证”。首轮人接触系数为 0，且根本不调用相关 loss。

### 9.3 数据加载、保存与恢复

将 pilot 的固定 inventory 扩展成显式 manifest Dataset，支持版本、资格资产、各任务部分标注与独立 box_aug 开关。字段名统一，原 WebDataset 路径保持可用；不强制将第一批全部迁成 tar。

用已导出纯 tensor state 严格初始化，不重复进行不必要的原 pickle 导出。完整训练 resume 需保存/恢复 optimizer、scheduler、实际 update、采样器/增强 epoch、随机流与数据清单版本；不能只加载网络参数后称“断点恢复”。

先做有限训练运行检查，再运行冻结预算。总 loss 下降不是效果验收；记录每任务有效点/正负例、实际更新、梯度与非有限事件、显存、耗时和重载一致性。选 checkpoint 的规则在运行前确定，不能事后挑一个改善最多的步数替代失败主结果。

## 10. 对照实验与评价

### 10.1 分阶段矩阵

| 阶段 | 目的 | 固定项与变量 |
| --- | --- | --- |
| B0 已完成 | 五样本原权重流程基线 | oracle 框/mask、FP32、既定样本 |
| B1 | 小型同图换框挑战＋扩展合格样本基线 | 原权重不变；只变框，GT 共同支持冻结 |
| L1 | 新 visibility 标签与训练读取验收 | 不以模型预测充当标签；新旧坐标链回归 |
| T1-off | 新数据坐标＋visibility 微调 | 框增强关闭；其他增强与 on 一致 |
| T1-on | 衡量框增强增益 | 同父样本、初权重、样本顺序、预算；独立扰动随机流 |
| T2 可选 | 预测 mask/框域适配 | 分割器固定，和纯框实验分开 |
| T3 待定 | 训练 floor-contact | 标签与正负例通过后单独启用 |

B1 和 L1/训练实现可以并行；不是必须完成每个历史小样本检查才允许讨论总体训练。正式 T1 依赖来源/标签/评价冻结，不能用未知 visibility 的旧数据冒充完整多任务训练集。旧可靠坐标样本可作为部分标签数据混入，比例明确。

推荐先 100–200 次真实更新作有界流程/趋势小试，之后根据实际吞吐、过拟合和独立验证决定扩展；此数值仍待批次评审，不是已授权训练命令。off/on 总更新和采样一致，mask/颜色等随机流不因框增强多抽随机数而被改变。

### 10.2 指标和验收

坐标：完整 ERP 点误差均值/中位数/P90、样本等权与点加权；可补单位射线角误差以解释 ERP 位置尺度差异。预测越界/非有限仍计失败，不能按预测 visibility/uncertainty 过滤主指标。分组至少含边缘/完整、骑行/行走、人数、环境、视角；遮挡分组仅用可信新 GT。

框鲁棒：同图同编号共同 GT 的误差与跨框预测漂移，新增严重失败率、有效支持率。预测漂移低不等于准确，两者同时报告。

双路：报告共同物理/crop 有效编号数量、各自 GT 残差；真正跨视角几何评价使用标定射线，必要时报告退化几何，不直接减两机像素，也不把配对残差叫合图误差。最终合图本批不改。

visibility：仅 known 集上报 BCE、PR-AUC、precision/recall、混淆矩阵、预测概率分布与校准；固定阈值与分组 unknown 比例。样本无正类/无负类的指标记不适用，不填满分。

完整对照：明确不许普通人物明显退化；建议后续冻结的候选门槛为困难组/框漂移相对改善约 10%、完整对照相对退化不超约 5%，且检查绝对量与尾部失败。**这些仅是建议，不是已通过或已批准标准**；基线误差小、样本少时须改用有意义的绝对阈值。比历史 DenseKP 的门槛更重要的是固定 MAMMA 自身基线。

时间稳定性：按 source time 和 GT 运动评估残差变化，不将真实快速动作误当抖动。统计单位是 episode/source group，多 rig/邻帧不是独立重复实验；小样本改善不得声称统计显著。

真实数据：冻结实际 detector/mask 版本与真实 20260320 标定；无 GT 时报告人工对照、可配对率、框变化和输出稳定性，不能报告真实定位精度。近期已看过的真实片段用于开发，不伪装未见测试。

## 12. 尚需决定的少数事项

1. **Visibility 语义**：是否采用首轮仅监督物理域内且 crop 内的可信点；推荐采用。官方衣物处理未核清时，是否接受明确命名的项目几何策略与 uncertain band；不能假称官方等价。
2. **Floor-contact**：推荐本轮设计接口、少量核验，后续阶段再训；用户只确定关闭 person contact，并未决定关闭 floor contact。
3. **参数更新范围**：推荐冻结 backbone/mask encoder，训练共享 decoder＋坐标/visibility 头；更保守末端头方案可作小试备选。
4. **数据规模与配额**：先测代表 episode 成本，再冻结约 8–12 train/4–6 dev 的候选规模；来源独立性与困难比例优先于帧数。
5. **最终输入口径与效果门槛**：明确实际 YOLO/其它分割分支；冻结 MAMMA 自身基线后确定绝对/相对改善与普通对照退化上限。

这些决定只影响对应依赖阶段；不阻塞 A3 继续编辑器，也不要求重新做已通过的权重加载、坐标适配或旧场景渲染。
