## 启动与操作

从仓库根目录执行 `python tools/scene_editor/server.py --port 8765`，本机打开 `http://127.0.0.1:8765`。VS Code 远程环境在端口面板转发 8765；服务仅绑定 `127.0.0.1`。当前会话中的服务已在该端口运行。简明操作见 `tools/scene_editor/README.md`。

选择城市或河岸，选中并拖动人物控制点或绑定双机中心；控制点也可按编号精确输入 X/Y。添加控制点须先点击右侧按钮，删除也在右侧执行；空白点击不会改动路线。滚轮缩放。时间轴选 0–30 帧，显示当帧人物的路线行进方向，检查当前时刻或全段；保存会新增带 revision 的配方。预览当前时刻仅选中一组 rig 的 cam2/cam4，预览区与正式 episode 分离；改动后旧预览标过期。生产按钮先做全段基础检查，再由后台冻结、精确预检、单 Blender 进程和常驻 CPU 消费者运行 31 帧。CLI 可用同一配方 `check`、`freeze`、`run`；使用方法见 README。

## 保存、冻结与安全边界

`scene_editor_recipe_v1` 保存场景、地图版本、世界 XY 米制、稳定人物 ID、实际资产引用及整数源帧、控制点/速度/进度、rig、31 帧时间表、渲染合同和 revision。`freeze` 生成现有 `scene_episode_rig_list_v1` prepared，人体、衣物、groom 与 R138 共用场景矩阵；原 motion 局部变化仍由已有资产帧驱动。适配时保留各注册 rig 的 ROI/框预留策略，裁去未选人物的 `component_provenance`。默认 64 samples、逻辑 ERP 5760×2880、ROI-only；单帧预览不打包正式序列，正式生产重渲该帧。API 检查场景、注册来源、资产、源时间、rig 标定、帧子集、渲染合同及受限保存 ID；不接受客户端任意 prepared 或命令路径。任务冻结 recipe，持久记录任务状态，取消仅终止本服务启动的进程组。

CPU 检查提供根轨迹、候选道路、根间距与相机根净空；冻结阶段再用生产几何、physical mask 和 ROI 规划器检查身体/衣物道路、接缝/裁剪与 ROI 像素上限。没有完整建筑碰撞、曲率/人体转弯包络、相机物理净空或独立边缘覆盖门槛验收；扇形/绿色道路不能视为精确许可。前端尚缺双路 physical/R138/框叠加层和完整覆盖统计面板，预览目前显示真实 ROI 图。不能把此版当正式来源独立性或边缘目标验收工具。所有新产物为 `integration_only`。

## 2026-10-15 交互修正

“添加控制点”模式优先处理点击，按画出的平滑曲线而非控制点连线计算距离；点在已有控制点上会在相邻曲线上插入，过密路段明确报错。机位模式允许点击地图放置所选双机组，并保留原 Z 安装高度。临时本地服务加 Chrome 实测：点在已有轨迹点上从 31 增至 32 点，撤销恢复；点击地图使 rig XY 改变且 Z 保持 0。此修正仅改前端及说明，未启动 GPU 或生成新 recipe/视频。用户需刷新页面加载新版。
